### 3.4 布局尺寸（实测，别改）

```
1440×900 的浏览器窗口，真实视口高度只有 807px
（剩下的是标签栏和任务栏）

三栏高度预算（807px 视口）：
  顶栏 40  +  主区 580  +  时间轴 97  +  间距/内边距 90

右栏三张卡的高度预算：
  当前状态 218  /  传感信号 246  /  一句结论 88   = 552（正好等于可用空间）
```

**这是踩过的坑**：按 900px 排版，右栏第三张卡会被裁掉 151px。**任何改动都要在这个预算里做，超出就压缩内容，不要靠滚动。**

### 3.5 三个已经踩过的坑

| 坑 | 现象 | 解法 |
|---|---|---|
| **CSS `filter` 用在 SVG 上** | 进度弧完全不渲染（尤其无 GPU 环境） | 用"宽描边低透明度 + 细描边渐变"两层画光晕，不依赖滤镜 |
| **`transition: .26s ease` 全局** | 切换按钮出现白底白字 | 只对 background-color / box-shadow 做过渡，颜色即时切换 |
| **`.metrics span{display:block}`** | 单位"次"被挤到第二行 | 选择器写 `.metrics>div>span`，别用后代选择器 |

## 4. 数据契约（最重要的一节）

`demo-session.html` 里只有一个状态对象 `S`，**所有渲染函数都读它**。你只要让 `S` 变成真的，界面就全对了。

```js
const S = {
  remain,       // 剩余秒数         ← session.js
  running,      // 是否在计时       ← session.js
  scene,        // 'paper' | 'screen' ← 用户选择
  score,        // 0-99 专注分      ← core/attention.js
  blocks,       // 60 格颜色历史    ← 每 5 秒 pushBlock()
  distract,     // 分心次数         ← F2 事件计数
  pauseCount,   // 停笔次数         ← core/action.js
  awaySec,      // 离座秒数         ← present=false 累计
  streakMax,    // 最长连续秒数     ← F5 连续 ≥65 的时长
  blink,        // 眨眼率 /分       ← health-monitor.js
  dist,         // 视距 cm          ← frame.distanceCm（场景 A 要改，见下）
  gaze,         // stable|drift|stare ← core/gaze-attention.js
  hand,         // writing|paused   ← core/action.js
  pauseSince,   // 当前停笔了多久   ← core/action.js
};
```

### 场景 A 的视距必须重算

`frame.distanceCm` 是基于**瞳距**估的。低头写字时瞳距被压缩，会算出"距离 90cm"这种假数据。

```js
// 场景 A 改用脸框宽度，不用瞳距
const distanceCmPaper = K / (frame.faceBox.w / frame.frameWidth);  // K 需实测标定
```

不修这条，护眼数据全是假的。

### 渲染函数不用重写

`updateRing()` / `updateHUD()` / `renderSignals()` / `pushBlock()` / `level()` 全部可以直接复用。**你只需要把 `simulate()` 删掉。**

## 5. 接线步骤（具体到文件）

### 第 1 步：手部测试页（先证明摄像头拍得到手）

新建 `hand-test.html`，要求：

```js
const { FilesetResolver, HandLandmarker } = await import('./vendor/mediapipe/vision_bundle.mjs');
const fileset = await FilesetResolver.forVisionTasks('./vendor/mediapipe/wasm');
const hand = await HandLandmarker.createFromOptions(fileset, {
  baseOptions: { modelAssetPath: './vendor/mediapipe/hand_landmarker.task', delegate: 'GPU' },
  runningMode: 'VIDEO',
  numHands: 2,
});
```

画面上要显示三件事：**21 个点、每只手的手掌尺度、实时位移能量**。

然后让 3 个人各写 2 分钟字，记录"手在画面里的比例"。**低于 80% 就要先解决摄像头角度，不要往下写代码。**

### 第 2 步：`src/core/action.js`（纯函数，必须可单测）

```js
export function handEnergy(landmarks, prev, palmSize)          // 位移能量
export function detectWritePause(hand, frame, base, now)        // 停笔
export function detectHandToFace(hand, frame, base)             // {drink, touchFace}
export function detectPageTurn(hand, prev, now)                 // 翻页
```

规则：**不依赖 DOM、不依赖摄像头**，输入普通对象、输出普通对象。这样能进 `tools/test-core.mjs` 跑单测（现在已有 34 项，接着加）。

停笔判定：

```js
const inWritingPose = frame.pitchDeg > base.pitch + 12;   // 头是低着的
const still = energy < T.writeEnergy;                      // 建议首版 0.015
if (inWritingPose && still && headStill) { /* 持续 15s → WRITE_PAUSE */ }
```

**阈值必须实测。** 采 3 分钟真写字、1 分钟发呆、若干干扰动作，取位移能量的 P5 和 P95，阈值取中间。方法见 `技术边界与信号路线.md` 第 5 节。

手到嘴（喝水 / 摸脸 / 托腮，一套逻辑，不认杯子）：

```js
const d = dist(hand.wrist, hand.mouth) / hand.faceWidth;
if (d < 0.12 && frame.pitchDeg < base.pitch - 8) → 喝水
if (d < 0.15 && !上仰)                            → 摸脸
```

### 第 3 步：把 demo 换成真数据

```js
// 1. 删掉这些
- function simulate() { ... }
- setInterval 里的 simulate()

// 2. 换成
const sess = new Session({ scene: 'paper', minutes: 25 });
sess.on('tick', (snap) => {
  S.remain    = snap.remain;
  S.score     = snap.focusScore;      // core/attention.js
  S.distract  = snap.distractCount;
  S.streakMax = snap.streakMax;
  S.hand      = snap.hand.state;      // core/action.js
  S.pauseSince= snap.hand.pauseSec;
  updateRing(); updateHUD();
});
setInterval(renderSignals, 900);      // 这一行保留

// 3. 每 5 秒
if (sec % 5 === 0) pushBlock();
```

**注意**：`S.blocks` 是 60 格的滚动窗口，`pushBlock()` 里已经处理了取模，不要自己再写一套。

## 6. 产品规则（不能改，改之前先问）

| 规则 | 内容 | 为什么 |
|---|---|---|
| **场景 A 关掉全部眼神判定** | 低头时虹膜不可见，硬算就是噪声 | 见技术边界文档第 2 节 |
| **情绪只做"面部状态占比"** | 报告里写"平静 78%、皱眉 15%"，不写"压力指数" | 最好的开源模型只有 63% |
| **不做时间乘法** | 不写"打断 7 次 × 23 分钟 = 损失 2.5 小时" | 25 分钟的会话不可能损失 2.5 小时 |
| **文案不说"你在发呆"** | 说"这一行盯了很久"、"停笔了 1 分 40 秒" | 指控性措辞会让人关掉功能 |
| **阈值宁可松不可紧** | 分心判定全部先调保守 | 用户被错记 5 次就卸载 |

完整阈值表：`开发文档-自律学习版.md` 附录 7。

## 10. 明确不要做

| 不做 | 原因 |
|---|---|
| 真实情绪模型（HSEmotion 等） | 63% 的准确率撑不起任何结论，还要两天 |
| 转笔识别 | 要自采 300 段数据训分类器，收益只有报告里一行字 |
| 云端排行榜 | 要后端要用户量，数据一定是假的 |
| 录视频回看 | 和"不上传不落盘"直接冲突 |
| 手机 App / 小程序 | 现场没人愿意装包 |
| 重写 UI 框架（React / Vue） | 现在这套原生 DOM 够用，换框架是纯风险 |

## 11. 三个要先验证的假设

按风险排，第一条不成立，后面全部作废。

1. **摄像头拍得到写字的手。** 笔记本摄像头通常朝上，写字的手在桌面下方，很可能完全不在画面里。这是整个场景 A 的地基。
2. **停笔和"思考"能分开。** 停笔 15 秒既可能是走神，也可能是认真想题。如果误报率高，就退回"只统计不判定"。
3. **单个笔记本能同时跑人脸 + 手部。** 两个模型各 10–20ms，30fps 下预算只有 33ms，必须实测。跑不动就把手部降到 10fps。
