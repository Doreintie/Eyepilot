## 0. 这次到底改了什么

**旧主线**：用眼睛代替鼠标，护眼是附带的。

**新主线**：你在学习的时候，AI 盯着你有没有真的在学。眼睛只是它的传感器之一。

这个转向的意义在于：**眼控是"炫技"，自律是"刚需"**。评委不会因为你能用眼睛点按钮而给你加分，但会认真听"我昨天专注了 4 小时，其中 47 分钟在走神"。

### 保留什么

| 模块                       | 处置                                                             |
| ------------------------ | -------------------------------------------------------------- |
| `vision.js` 视觉管线         | ✅ 完全复用，一行不改。**`hxL/hyL/hxR/hyR` 四个眼内偏移量是本次的核心新武器**，见 F10       |
| `gaze.js` 九点校准           | ⚠️ 保留但降级。自律场景不该要求用户先校准 20 秒，所以坐标映射只在"视线出屏"里用，主力换成 F10 的免校准特征   |
| `health-monitor.js` 健康指标 | ✅ 复用，缩成报告里的一个区块                                                |
| `ai.js` AI 教练            | ✅ 复用，改为解读"专注报告"                                                |
| `plugins/focus.js` 番茄钟   | 🔧 作为底座重写，是本次主战场                                               |
| 眼控指针 / 四档控制模式 / 插件系统     | ✅ **代码全部保留，不删不藏**。界面不再以它为主，但 F1 会话结束时提供"用眼睛点结束/休息"的入口，作为差异化演示点 |

### 新增什么

| 能力 | 用途 | 依赖模型 | 见 |
|---|---|---|---|
| 手部 21 点 | 停笔、喝水、摸脸、翻页 | Hand Landmarker（7.8MB） | **F11** |

## 2. 数据模型

### 2.1 会话（Session）

一次完整的专注计时 = 一个 Session。

```js
{
  id: 's_1732618800000',        // 时间戳字符串
  startedAt: 1732618800000,     // 开始时间戳（ms）
  endedAt: 1732619700000,       // 结束时间戳
  plannedMs: 1500000,           // 计划时长（25 分钟）
  actualMs: 1480000,            // 实际计时时长（扣掉暂停）
  pausedMs: 20000,              // 累计暂停时长

  // 核心结果
  focusRate: 0.87,              // 专注率 = 有效专注 / 实际时长
  focusMs: 1287600,             // 有效专注时长
  distractCount: 7,             // 分心总次数
  longestStreakMs: 612000,      // 最长连续专注
  focusScoreAvg: 84,            // 平均专注度

  // 事件明细
  events: [
    { type: 'TURN', start: 1732618900000, end: 1732618904000, durMs: 4000 },
    { type: 'AWAY', start: 1732619100000, end: 1732619115000, durMs: 15000 }
  ],

  // 时间序列（采样，每 5 秒一个点）
  series: [
    { t: 1732618800000, focus: 92, frust: 0.1, fatigue: 0.2, engagement: 0.8 },
    ...
  ],

  // 分项
  posture: { up: 3, down: 12, turn: 5 },   // 抬头/低头/转头 次数
  emotion: { dominant: 'engaged', avgFrust: 0.18, avgFatigue: 0.31 },
  eyeCare: { blinkPerMin: 14, completeRatio: 0.62, avgDistanceCm: 58 }
}
```

### F1 · 专注会话管理

#### 目标

管理一次专注计时从开始到结束的完整生命周期，产出 F2–F9 所需的上下文。

#### 输入

用户操作（开始 / 暂停 / 继续 / 提前结束）。

#### 状态机

```
        ┌────────┐  点击开始   ┌──────────┐
        │ IDLE   ├────────────→│ RUNNING  │
        │ 未开始  │             │ 计时中    │
        └────────┘             └────┬─────┘
              ▲                     │
              │ 重置          ┌─────┴─────┐
              │               │ 点击暂停   │ 计时归零
              │               ▼           ▼
              │         ┌──────────┐  ┌──────────┐
              └─────────┤ PAUSED   │  │ FINISHED │
                        │ 暂停中    │  │ 已完成    │
                        └────┬─────┘  └──────────┘
                             │ 继续
                             └──→ RUNNING
```

#### 规则

| 规则       | 说明                                                                                           |
| -------- | -------------------------------------------------------------------------------------------- |
| 时长预设     | 25 / 45 / 60 / 90 分钟 + 自定义（5–180）                                                            |
| **学习场景** | 开始前必选，两级：**场景 A 纸质学习**（写字 / 看书 / 做卷子）、**场景 B 电脑学习**（看网课 / 写代码 / 刷题）。场景决定启用哪套引擎：场景 A 关掉全部眼神判定（低头时看不到虹膜），改用停笔判定；场景 B 全开 F10。见 F11 与 `技术边界与信号路线.md` 第 2 节 |
| **任务细类** | 场景 B 下再选：阅读 / 刷题 / 写代码 / 看网课。只用于 F10 的 G2 开关（看网课时跳视天然少，不区分会大面积误报） |
| 暂停       | 暂停期间**不计入**实际时长，也不算分心                                                                        |
| 提前结束     | 允许，但报告标注「提前结束」，不计入连续专注纪录                                                                     |
| 自动结束     | 倒计时归零 → 自动生成报告                                                                               |
| 休息       | 完成后提示 5 分钟休息，休息期间不采集                                                                         |

#### 代码位置

- 新建 `src/session.js`：`class Session { start(), pause(), resume(), finish(), snapshot() }`
- 改造 `src/plugins/focus.js`，把计时逻辑抽到 `session.js`，插件只做 UI

#### 验收标准

- [ ] 暂停 10 秒后继续，`actualMs` 不包含这 10 秒
- [ ] 中途关页面，重开能检测到未完成会话并提示（可选 P1）
- [ ] 提前结束的会话 `finishedByUser = true`

### F2 · 分心识别引擎（核心）

#### 目标

把每秒的 `frame` 判定成"是否在分心"，输出带起止时间的事件流。**这是整个产品的技术核心。**

#### 输入

```js
frame = {
  t, present,          // 是否检测到人脸
  yawDeg, pitchDeg,    // 头部真实角度（度）
  open,                // 睁眼度 0–1
  raw                  // 含 faceBlendshapes
}
```

#### 判定表

| 事件       | 判定条件                                    | 阈值    | 最短持续       | 说明              |
| -------- | --------------------------------------- | ----- | ---------- | --------------- |
| `AWAY`   | `present === false`                     | —     | **2000ms** | 人脸完全丢失，最确定的分心   |
| `DOWN`   | `pitchDeg < base.pitch - 22`            | 22°   | **2500ms** | 低头，大概率在看手机      |
| `UP`     | `pitchDeg > base.pitch + 18`            | 18°   | **2500ms** | 抬头看别处           |
| `TURN`   | `abs(yawDeg - base.yaw) > 30`           | 30°   | **2500ms** | 转头              |
| `GAZE`   | 眼内偏移超基线（自适应 ±3σ，见 **F10 G1**），或已校准时视线出屏 | 见 F10 | **2000ms** | 头没动，眼睛跑了        |
| `DROWSY` | `open < 0.35`                           | 0.35  | **1500ms** | 长时间闭眼           |
| `BLINK`  | 闭眼但 < 300ms                             | —     | —          | **不算分心**，自然眨眼豁免 |

> 📌 以上阈值的依据见 `分心判定调研与阈值依据.md`。**不要凭感觉改这些数字**，先读那份文档第 5 节。

> `base` = 会话开始后前 5 秒的姿态中位数，**每次会话重新采集**。用户换坐姿就要重来。

#### 状态机（每个事件类型独立跑一份）

```js
// 每个类型维护一个实例
function updateEvent(state, conditionMet, now, minDuration) {
  if (conditionMet) {
    if (state.since === 0) state.since = now;          // 开始计时
    if (!state.active && now - state.since >= minDuration) {
      state.active = true;
      state.start = state.since;
      onEventBegin(state.type, state.start);
    }
    if (state.active) {
      state.lastHit = now;
      state.quietSince = 0;
    }
  } else {
    if (state.active) {
      // 防抖：条件消失也要连续 1200ms 才认为真的结束
      if (state.quietSince === 0) state.quietSince = now;
      if (now - state.quietSince >= T.exitQuietMs) {
        state.active = false;
        onEventEnd(state.type, state.quietSince);
        state.since = 0;
        state.quietSince = 0;
      }
    } else {
      state.since = 0;                                  // 没够时长就消失了，作废
      state.quietSince = 0;
    }
  }
}
```

#### 关键设计原则

1. **单帧不判定**。人脸检测每秒都有 1–2 帧抖动，必须靠"最短持续"过滤。
2. **进入难、退出也难**。进入要 2.5 秒，退出要连续 500ms 干净，防止反复横跳。
3. **事件可重叠**。可能同时"低头"+"视线游离"，报告里按主事件归类（优先级 `AWAY > DOWN > TURN > UP > GAZE > DROWSY`）。
4. **暂停时不判定**。用户主动暂停期间一切都是合法的。

#### 专注率的计算

```js
// 分心总时长 = 所有事件时长之和（重叠部分只算一次）
const distractedMs = unionDuration(events);
const focusMs = actualMs - distractedMs;
const focusRate = focusMs / actualMs;
```

> ⚠️ 用**并集**算，不是简单相加。两个事件重叠时加两次会把专注率算低。

#### 代码位置

- 新建 `src/core/attention.js`：纯函数，**必须可单测**
  - `createEventTracker()`
  - `updateFrame(trackers, frame, base, now)`
  - `unionDuration(events)`
- 新建 `src/core/posture.js`：base 采集与头位判定

#### 验收标准

- [ ] 合成 frame（低头 30°）喂 3 秒 → 产生 1 条 DOWN 事件，`durMs` ≈ 3000
- [ ] 低头只喂 1 秒 → **不产生**事件
- [ ] 两个事件重叠时，`unionDuration` 不重复计算
- [ ] 会话暂停期间喂 frame → **不产生**任何事件

### F3 · 头位偏离统计（抬头 / 低头 / 转头）

#### 目标

单独统计姿态变化次数，用于报告里的"你抬头了几次、低头了几次"。

#### 与 F2 的区别

- **F2 是"分心判定"**：综合了持续性、其他信号，关心"这段是不是没在学"
- **F3 是"姿态统计"**：只数头动了多少次，不判断是不是分心

一次 10 秒的低头，在 F2 里记 **1 次分心**，在 F3 里记 **1 次低头**。但一次 1 秒的低头，F3 记 1 次，F2 不记。

#### 判定

复用 `base`，阈值比 F2 更宽松（因为只是计数，不扣专注率）：

| 方向 | 条件                            | 最短持续  |
| -- | ----------------------------- | ----- |
| 抬头 | `pitchDeg > base.pitch + 12`  | 800ms |
| 低头 | `pitchDeg < base.pitch - 15`  | 800ms |
| 转头 | `abs(yawDeg - base.yaw) > 20` | 800ms |

#### 代码位置

`src/core/posture.js` 内，与 F2 共用 `base`，独立计数。

#### 验收标准

- [ ] 快速点头 5 次（每次 1 秒）→ `posture.down === 5`
- [ ] 长时间低头 1 次 30 秒 → `posture.down === 1`（不是 30）

### F4 · 情绪状态分析

#### 目标

从表情推断 4 个维度的粗粒度状态，画成曲线放进报告。

#### 数据源

`frame.raw.faceBlendshapes[0].categories` —— 52 个 blendshape 分数。

用到的：

| blendshape                           | 含义         |
| ------------------------------------ | ---------- |
| `browDownLeft` / `browDownRight`     | 皱眉         |
| `mouthFrownLeft` / `mouthFrownRight` | 嘴角下撇       |
| `mouthSmileLeft` / `mouthSmileRight` | 嘴角上扬       |
| `jawOpen`                            | 张嘴（打哈欠/说话） |
| `eyeSquintLeft` / `eyeSquintRight`   | 眯眼         |
| `noseSneerLeft` / `noseSneerRight`   | 鼻翼皱起       |

#### 四个维度的计算

```js
const avg = (a, b) => (a + b) / 2;
const bs = (name) => categories[name] || 0;

const brow    = avg(bs('browDownLeft'),    bs('browDownRight'));
const frown   = avg(bs('mouthFrownLeft'),  bs('mouthFrownRight'));
const smile   = avg(bs('mouthSmileLeft'),  bs('mouthSmileRight'));
const squint  = avg(bs('eyeSquintLeft'),   bs('eyeSquintRight'));
const sneer   = avg(bs('noseSneerLeft'),   bs('noseSneerRight'));
const jaw     = bs('jawOpen');

// 挫败：皱眉 + 嘴角下 + 鼻翼
const frustration = clamp01(0.55 * brow + 0.30 * frown + 0.15 * sneer);

// 疲惫：闭眼 + 眯眼 + 打哈欠（张嘴）
const fatigue = clamp01(0.45 * (1 - frame.open) + 0.30 * squint + 0.25 * jaw);

// 投入：睁眼 + 不皱眉 + 微笑
const engagement = clamp01(0.45 * frame.open + 0.30 * (1 - brow) + 0.25 * smile);

// 困惑：皱眉 + 咬牙（用 jaw 近似）+ 眯眼
const confusion = clamp01(0.50 * brow + 0.30 * squint + 0.20 * jaw);
```

#### 平滑（必须做）

单帧表情噪声极大，**禁止直接画到曲线上**。

```js
// EMA 平滑，α 越小越稳
const ALPHA = 0.12;
state.frustration += (rawFrustration - state.frustration) * ALPHA;
```

或者用 3 秒滑窗取中位数（更抗尖峰）。

#### ⚠️ 诚实边界（必须写进 UI 和答辩）

**这不是情绪识别，是表情倾向估算。**

- 普通 RGB 摄像头无法可靠区分"皱眉思考"和"皱眉生气"
- 亚洲人脸的表情幅度普遍较小，blendshape 分数偏低
- 打哈欠和张嘴说话在数据上几乎一样
- **准确率不要写任何具体数字**，写"行为学估算，仅供参考"

在报告里必须标注：

> 情绪数据来自面部表情的行为学估算，不能作为心理状态判断依据。

#### 代码位置

- 新建 `src/core/emotion.js`：`computeEmotion(frame)` → `{frustration, fatigue, engagement, confusion}`
- 纯函数，可单测

#### 验收标准

- [ ] 输入全 0 的 blendshape → 四个维度都是有限值（不能 NaN）
- [ ] `frame.open = 0`（闭眼）→ `fatigue > 0.4`
- [ ] `browDown` = 1、其余 0 → `frustration > 0.5`
- [ ] EMA 平滑后，单帧尖峰不会让曲线跳变超过 0.2

### F5 · 专注度实时评分

#### 目标

把多个信号融合成一个 0–100 的分数，供实时显示和报告使用。

#### 公式

```js
// 各分量都是 0–1
const presentRatio   = 窗口内在座帧 / 总帧;        // 在座率
const gazeStability  = 1 - clamp01(|ex - base.ex| / thrX); // 视线稳定度（免校准，见 F10）
const headStability  = 1 - clamp01(头位偏离幅度 / 30); // 头稳不稳
const engagement     = emotion.engagement;         // 表情投入

const focusScore = Math.round(100 * (
  0.35 * presentRatio +
  0.25 * gazeStability +
  0.20 * headStability +
  0.20 * engagement
));
```


#### 窗口
滑动 **60 秒**，每秒重算一次。不要用全历史（反应太慢）。

#### 分级（用于界面配色和文案）

| 分数 | 状态 | 颜色 | 文案 |
|---|---|---|---|
| 85–100 | 深度专注 | 绿 | 状态很好，继续保持 |
| 65–84 | 正常专注 | 蓝 | 在轨道上 |
| 40–64 | 轻度分心 | 黄 | 感觉你有点飘 |
| 0–39 | 明显分心 | 橙 | 要不要先休息一下 |

#### 代码位置
`src/core/attention.js` 内 `computeFocusScore(window)`。

#### 验收标准
- [ ] 全程在座、头不动、表情中性 → 分数 > 85
- [ ] 全程人脸丢失 → 分数 → 0
- [ ] 分数变化不会单帧跳变超过 25 分（要平滑）

### F6 · 实时可视化界面

#### 目标
**这是产品的门面。** 用户要能在计时过程中一眼看到"我现在是什么状态"。

#### 关键组件

**1. 环形计时器**
- SVG 圆环，`stroke-dashoffset` 驱动
- 颜色随时间变化：正常蓝 → 最后 1 分钟橙 → 结束绿
- 中心显示剩余时间和当前状态文字

**2. 状态灯**
- 一个圆点 + 文字，随专注度实时变色
- 变化要有 300ms 过渡，不要闪烁

**3. 专注时间轴（最重要）**
- 横向色块条，每 5 秒一个色块
- 颜色映射专注度：绿（>85）/ 蓝（65–84）/ 黄（40–64）/ 橙（<40）/ 灰（离座）
- 只显示最近 5 分钟，滚动前进
- **用户一眼就能看到"我刚才是不是在摸鱼"**

**4. 情绪条**
- 三个横向进度条：投入 / 疲劳 / 挫败
- 数值不要写数字，写文字（平静 / 略疲劳 / 明显疲劳）

**5. 摄像头小窗**
- 右下角，160×120，显示关键点和当前帧
- **可关闭**（有人会介意一直拍着）

**6. 眼神指示（F10，路演的杀手镜头）**
- 在摄像头小窗旁边加一行极简指示：`眼神 ●`，三态
  - 灰：正常（眼在眶中央、扫视正常）
  - 黄：偏移（G1，眼睛飘走了）
  - 紫：凝固（G2，盯着不读）
- **一定要让评委看到"紫色"出现的过程**：让演示者头保持不动、眼睛盯着屏幕不动 8 秒，指示器从灰变紫。这是全场唯一一个"头没动、眼没偏，但它知道"的瞬间，比任何参数都有说服力

#### 状态提示文案（要有温度，不要像监工）

| 触发 | 文案 |
|---|---|
| 首次分心 | 没关系，把注意力拉回来 |
| 5 分钟内 3 次以上 | 已经第 3 次啦，要不要调整一下坐姿 |
| 连续专注 10 分钟 | 连续 10 分钟了，很棒 |
| 疲劳 > 0.6 | 看起来有点累了，撑不住就休息 |
| 离座超过 30 秒 | 离开了？计时还在走哦 |
| **眼神偏移（G1）** | 眼睛好像飘走了，还在这一页吗 |
| **注视凝固（G2）** | 这一行盯了很久，要不要先标记一下再回来 |
| **走神型眨眼升高（G3）** | 眨得有点频，是不是在想别的事 |

> G2 的文案故意写成"这一行盯了很久"而不是"你在发呆"——**同样的判定，说法不同，用户接不接受完全不同**。指控性措辞会让人关掉这个功能。

> ⚠️ **产品伦理**：这是"督促"不是"监视"。措辞必须站在用户这边，不能像老板盯工。绝不做"惩罚"机制。

### F10 · 眼神注意力引擎（眼控保留下来的部分，用在这里）

#### 定位：眼控不是被砍掉，是换了工种

| | 旧主线（眼控产品） | 新主线（自律产品） |
|---|---|---|
| 眼睛的作用 | **输出**：代替鼠标点按钮 | **输入**：判断你有没有在学 |
| 关键动作 | 把眼球位置映射成屏幕坐标 | 读眼球相对眼眶的偏移、扫视节奏、眨眼节律 |
| 要不要校准 | 必须，否则点不准 | **基本不要**，只有出屏判定需要 |
| 代码 | `gaze.js` 九点校准 + 光标渲染 | 新增 `core/gaze-attention.js` |

理由很实际：**没有人会在开始 25 分钟学习之前先做 20 秒校准。** 所以自律场景里，凡是需要绝对屏幕坐标的信号都得降级；凡是**相对量**都能直接用。

而 `vision.js` 已经把相对量算好了，一行都不用改：

```js
// 虹膜相对「内外眼角中点」的偏移，用两眼平均眼宽归一化
// 注意：眼角中点不随眼睑开合变化，眨眼时不会跳
hxL, hyL, hxR, hyR   // 范围约 ±0.55，两眼方向已统一、共用同一尺度
```

这两个设计细节决定了它可用：**用眼角中点而不是眼眶包围盒**（眨眼不抖）、**两眼共用尺度**（头转动时近眼变大不会被误当成视线位移）。组员不用重做特征工程。

#### G1 · 眼头不一致（进专注率，最强的一个）

**原理**：人看屏幕时，头和眼的朝向基本一致。当"头还端坐着、眼睛已经跑了"（看手机、看旁边的人、发呆），眼球会持续偏向一侧且**不回来**。

**计算**（全程免校准）：

```js
// 两眼平均的水平/垂直眼内偏移
const ex = (frame.hxL + frame.hxR) / 2;
const ey = (frame.hyL + frame.hyR) / 2;
```

**前提门控**（很重要，否则头转动会污染判定）：

```js
// 只在这些条件成立时才评 G1；头转了交给 TURN 事件处理
const headSteady =
  Math.abs(frame.yawDeg   - base.yaw)   < 10 &&
  Math.abs(frame.pitchDeg - base.pitch) < 12;
```

**判定**：

```js
// 自适应阈值：用基线期标准差，避免不同眼型套同一个数
const thrX = Math.max(0.10, 3.0 * base.stdEx);   // 0.10 ≈ 半个虹膜宽度
const thrY = Math.max(0.09, 3.0 * base.stdEy);

const drift = headSteady &&
  (Math.abs(ex - base.ex) > thrX || Math.abs(ey - base.ey) > thrY);
// 持续 ≥ 2000ms → GAZE_DRIFT
```

`base.ex / base.ey / stdEx / stdEy` 用会话前 5 秒采集（和 F2 的 `base` 同一次采集，不要采两遍）。

**为什么要 2 秒**：一次正常看屏幕边角（看时间、看进度条）也会大幅偏，但会马上回来。**只有持续 2 秒不回来才是"眼睛跑了"。**

**判定不了什么**：眼睛偏 ≠ 一定在看别的东西，也可能在看屏幕上很边角的位置。所以 G1 只判定"视线脱离工作区"，不判定"在看手机"——那个归因交给 F4 的标签，不要写死。

#### G2 · 注视凝固（只做标签，不进专注率）

**原理**：人在真正阅读或看内容时，眼睛每秒跳 3–5 次（跳视 saccade）。**如果眼睛连续 8 秒几乎不动，说明它在"盯着"而不是在"看"——这是走神（mind wandering）最典型的生理特征，也是所有基于头部的方案完全看不见的。**

这是整个 F10 里最值得讲的信号：**头没动、眼没偏、但它知道你不在。**

**计算**：

```js
// 每秒归一化移动速度
const dt = (now - prev.t) / 1000;
const v  = Math.hypot(ex - prev.ex, ey - prev.ey) / dt;

const isSaccade = v > 1.0;      // 跳视：速度快、幅度大
// 注视漂移通常在 0.02–0.1/s，跳视在 2–5/s，两者差一个数量级，阈值很好定
```

**判定**：

```js
// 8 秒滑窗内跳视次数
if (saccadesInWindow < 5 && Math.abs(ex - base.ex) < thrX) {
  // 眼没偏 + 几乎不跳 → GAZE_STARE（盯着发呆）
}
```

**⚠️ 必须按任务类型开关**：看视频、盯图表时跳视天然很少，直接判定会大面积误报。所以 **F1 会话开始时让用户选任务类型**（阅读 / 写代码 / 看网课 / 刷题），G2 只在"阅读、刷题"下启用，其他类型只记录不判定。

#### G3 · 眨眼节律（只做标签 + 护眼，双向用）

同一个指标，两个方向指向两种完全不同的状态：

| 模式 | 眨眼率 | 伴随 | 结论 |
|---|---|---|---|
| 走神型 | **↑ > 25 次/分** | G2 触发、`engagement` 不低 | 眼睛在屏幕上，脑子走了 |
| 疲劳型 | **↓ < 8 次/分** | 平均 `open` 低、眨眼时长变长 | 该休息了 |

**为什么这条有价值**：走神时眨眼增多、疲劳时眨眼减少，两个方向都能读出来。只用"眨眼太少提醒护眼"是浪费了这个信号。

眨眼事件检测复用现有逻辑（`open` 从 >0.6 跌到 <0.3 再回升算一次），60 秒滑窗统计。

#### G4 · 视线出屏（可选增强，需校准）

只有这一项需要 `gaze.js` 的九点校准。作用：用户手动校准过就用，没校准就跳过，**不要为了它强制校准**。

```js
const g = gaze.getScreenPoint(frame);       // 需要已校准
const off = g.x < 0 || g.x > W || g.y < 0 || g.y > H;
// 持续 3000ms → 合并进 G1，不单独出事件
```

#### 质量门控（不做这个，噪声会毁掉一切）

MediaPipe 在 640×480 下虹膜直径只有约 10px，**1px 误差就等于 10% 眼宽**。所以：

1. **闭眼帧直接丢弃**：`open < 0.5` 或 `blinkL/blinkR > 0.4` 的帧不参与 G1/G2
2. **眯眼降权**：`eyeSquint > 0.4` 时眼睑遮挡虹膜，把该帧权重降到 0.3（不是丢弃，否则眯眼学习的人会被判成"无数据"）
3. **表情干扰降权**：皱眉严重时眼角点会被带动，`browDown > 0.5` 时同样降权
4. **平滑**：`ex/ey` 先过 3 帧中值滤波再算速度，否则单帧跳点会被算成跳视

> 第 2、3 条用的是 F4 的 blendshape 输出——**表情引擎反过来给眼神引擎做质量门控**，两个模块不是各自算各自的。

#### 微表情怎么用：只做归因，不做判据

**不要用微表情判定分心。** 皱眉可能是深度思考（好事），也可能是烦躁（坏事），同一个信号指向相反结论，用它判定必然反向。这一点在 `分心判定调研与阈值依据.md` 里有数据支撑（FER2013 上专用模型只有 59.28%）。

**正确的用法是给事件打标签**：当一个 `GAZE_DRIFT` / `GAZE_STARE` 事件结束时，回看事件前 10 秒的 F4 平均值：

| 事件前 10 秒 | 报告里写 |
|---|---|
| `frustration` 高 | 「这次分心前你在皱眉，可能卡住了」 |
| `fatigue` 高 | 「这次分心前你有点累，不是不专心」 |
| `confusion` 高 | 「这次分心前表情偏困惑，可能是没看懂」 |
| `engagement` 不低但 G2 触发 | 「眼睛一直在屏幕上，但没在扫视——走神了」 |

这个用法**安全且是加分项**：它把"你又走神了"这种指责，变成"你走神是因为卡住了"，产品态度完全不同。评委听到这句会记住。


#### 代码位置

- 新建 `src/core/gaze-attention.js`：纯函数
  - `createGazeState()`
  - `updateGaze(state, frame, base, now)` → `{ drift, stare, saccades }`
  - `blinkRate(events, windowMs)`
- `src/core/posture.js`：`base` 里加 `ex/ey/stdEx/stdEy`（和 F2 同一次采集）
- `src/core/emotion.js` 输出 `squint/brow` 供质量门控用

#### 验收标准

- [ ] 合成 hx 从 0 跳到 0.20 并保持 2.5 秒（`yawDeg` 不变）→ 产生 1 条 `GAZE_DRIFT`
- [ ] 同上但只保持 1 秒 → **不产生**事件
- [ ] `yawDeg` 偏 20° 且 hx 偏移 → 只记 `TURN`，**不记** `GAZE_DRIFT`
- [ ] hx 全程静止 10 秒 → 产生 1 条 `GAZE_STARE`
- [ ] 模拟阅读序列（每 250ms 跳 ±0.05）→ **不产生** `GAZE_STARE`
- [ ] 闭眼帧（`open=0`）连续 3 秒 → 不产生任何 gaze 事件，只产生 `DROWSY`
- [ ] 眨眼瞬间的 hx 抖动（±0.15 单帧）→ 不产生跳视计数

#### 与 F2 / F5 的关系

| 信号 | 进专注率 | 进实时界面 | 进报告 |
|---|---|---|---|
| G1 `GAZE_DRIFT` | ✅ 计入分心时长 | ✅ 状态条 | ✅ 次数 + 时长 |
| G2 `GAZE_STARE` | ❌（按任务类型可开） | ✅ 显示"疑似走神" | ✅ 标签 + 归因 |
| G3 眨眼节律 | ❌ | 只显示异常时 | ✅ 走神型/疲劳型 |
| G4 视线出屏 | ✅ 并入 G1 | 否 | 否 |

**F5 公式要改一处**：`gazeStability` 不能再是"注视离散度"（那需要校准），改成 `1 - clamp01(|ex - base.ex| / thrX)`。这样 F5 也变成免校准的了。

### F11 · 动作检测（场景 A 的主力，也是全场最可靠的信号）

#### 为什么要有这一节

F10 的眼神判定有一个前提：**眼睛得看得见**。用户低头写字、看书的时候，摄像头里是头顶和侧脸，虹膜基本不可见，G1/G2 全部失效。

而"低头学习"恰恰是这个产品最主要的使用场景之一。所以场景 A 必须换一路信号：**不看眼睛，看手。**

动作信号的三个优势：幅度大（几十到上百像素，不是 10px 的虹膜）、免校准、可解释（"你的手停了 15 秒"比"模型输出 0.71"有力）。

> 完整论证见 `技术边界与信号路线.md` 第 1、2 节。

#### 输入

```js
hand = {
  t, present,
  wrist: {x, y},           // 归一化 0–1
  landmarks: [...21],      // 每只手 21 点
  palmSize,                // 手掌尺度，用于归一化
  mouth: {x, y},           // 来自 F2 的 face 帧（面部关键点）
  faceWidth,
}
```

数据源：MediaPipe **Hand Landmarker**，模型 `vendor/mediapipe/hand_landmarker.task`。
**注意：现有 `vision_bundle.mjs` 已经导出 `HandLandmarker`，不需要引任何新运行时**，只要加载模型文件。

#### 核心判据一：停笔（场景 A 的分心信号）

```js
// 1. 手部位移能量：5 帧（约 170ms）内的平均移动距离，用手掌尺度归一化
const energy = meanDist(hand.landmarks, prevLandmarks) / hand.palmSize;

// 2. 只有在"确实在写字/看书"的姿势下才评停笔
const inWritingPose = frame.pitchDeg > base.pitch + 12;   // 头是低着的

// 3. 手不动 + 头不动 = 停笔
const still = energy < T.writeEnergy;    // 建议首版 0.015，必须实测标定
if (inWritingPose && still && headStill) {
  // 持续 15000ms → WRITE_PAUSE
}
```

**阈值必须实测，不能拍脑袋。** 标定方法见 `技术边界与信号路线.md` 第 5 节：采 3 分钟真写字、1 分钟发呆、若干干扰动作，取位移能量的 P5 和 P95，阈值取中间。

#### 核心判据二：手到嘴（喝水、摸脸、托腮，一套逻辑）

不认杯子，只算距离。这样连透明水杯、马克杯、保温杯都不用管：

```js
const d = dist(hand.wrist, hand.mouth) / hand.faceWidth;

// 喝水：手到嘴 + 头轻微上仰
if (d < 0.12 && frame.pitchDeg < base.pitch - 8) → DRINK（持续 1200ms）

// 摸脸 / 托腮：手到脸，但头不上仰
if (d < 0.15 && !上仰) → TOUCH_FACE（持续 2000ms）
```

三个动作共用一套距离计算，只差阈值和伴随条件。**这是性价比最高的一组动作检测**：不用物体检测，不用训练，半小时能写完。

#### 其他动作

| 动作 | 判据 | 依赖 |
|---|---|---|
| 翻页 | 手部横向位移 > 0.25 屏宽，在 0.3~1.2s 内完成 | Hand |
| 离座 | `present === false` > 2000ms | Face |
| 抬头离开纸面 | `pitchDeg` 回到 base ±8° 内，且手不动 > 5000ms | Face + Hand |
| 伸懒腰 | 双腕 y 高于肩 y，双肩 y 上移 | Pose（P2，可选） |
| 看手机 | COCO `cell phone` 检测 + 低头 | ObjectDetector（P2，可选） |

> **"看手机"这个统计的真实含义是"低头 + 手机入镜"。** 用户把手机放桌下刷，摄像头拍不到，只能靠低头推断。所以文案必须写"低头（可能在看手机）"，不能写"看了 3 次手机"。

#### 场景 A 的护眼必须单独修

这里有个坑：`frame.distanceCm` 是基于**瞳距**估的，低头侧脸时瞳距被压缩，会算出"距离 90cm"这种假数据。

```js
// 场景 A 改用脸框宽度估算，不用瞳距
const distanceCmPaper = K / (faceBox.w / frameWidth);   // K 需实测标定
```

同时场景 A 要新增一个指标：**连续低头时长**。写字时视距常不到 30cm，低头角度大，颈椎和近视风险都比看屏幕高，护眼在这里反而更重要。

#### 代码位置

- 新建 `src/core/action.js`：纯函数
  - `handEnergy(landmarks, prev, palmSize)`
  - `detectWritePause(hand, frame, base, now)`
  - `detectHandToFace(hand, frame, base)` → `{drink, touchFace}`
  - `detectPageTurn(hand, prev, now)`
- 新建 `src/vision-hand.js`：封装 HandLandmarker，按 **10~15fps** 跑（不要 30fps，浪费）
- 改造 `src/vision.js`：`blendshapes` 挂到 `frame` 上

#### 验收标准

- [ ] 真写字 3 分钟 → `WRITE_PAUSE` 触发 **0 次**
- [ ] 停笔不动 20 秒 → 产生 **1 条** `WRITE_PAUSE`，时长 ≈ 20s
- [ ] 抬手翻页 → **不产生** `WRITE_PAUSE`（手在动）
- [ ] 手抬到嘴前且头微仰 → 产生 1 条 `DRINK`，且 **2 秒内的重复帧不重复计数**
- [ ] 手摸下巴但头不动 → 产生 `TOUCH_FACE`，**不产生** `DRINK`
- [ ] 手不在画面里 → 所有手部判据返回 `null`（不是 `false`），上层据此跳过而不是记分心
- [ ] 四个模型同时跑时总耗时 < 25ms（分频调度生效）

## 6. 风险与取舍

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| **阈值误判**（稍微一动就记分心） | 高 | 致命 | 最短持续 2.5 秒 + 退出防抖 1200ms + 眨眼豁免 300ms；现场用「灵敏度」滑杆可调 |
| **情绪数据难看**（一直是 0） | 中 | 中 | 表情分数低是常态，界面用文字不用数字；不画绝对值曲线，画相对趋势 |
| **排名被质疑** | 高 | 中 | 只用方案 A（超过自己），保留原始数据可现场核对 |
| **专注率算低**（重叠事件重复计算） | 中 | 高 | 必须用 `unionDuration`，并写单测 |
| **手机/镜头不好导致 present 频繁 false** | 中 | 高 | 人脸丢失 2 秒才判定；低置信度时暂停判定而不是记分心 |
| **演示时一直被判定分心** | 中 | 致命 | 准备「演示模式」：用合成数据跑完整流程，讲逻辑而非实时 |
| **虹膜点抖动**（F10 特征噪声大，640×480 下虹膜仅约 10px） | 高 | 中 | 3 帧中值滤波 + 3σ 自适应阈值 + 闭眼/眯眼/皱眉帧降权；G1 要求持续 2 秒，让噪声被时间平均掉 |
| **G2 在看视频时大面积误报** | 高 | 中 | 按任务类型开关（只在阅读/刷题下启用）；误报时退回"只打标签不进专注率" |
| **眼神数据被当成"监视"** | 中 | 高 | 界面上眼神指示只有三态、不显示原始数值；报告里措辞用"这一行盯了很久"不用"你在发呆" |
| **场景 A 手不在画面里**（写字时手在桌面下方，笔记本摄像头拍不到） | 高 | 高 | 上台前调整摄像头角度让手腕入镜；**拍不到手就退化成"低头时长 + 抬头次数"判定**，停笔功能关闭并在界面明说"手未入镜，已降低精度" |
| **四个模型同时跑掉帧** | 高 | 高 | 分频调度是硬要求（脸 30 / 手 12 / 物体 1 / 姿态 1）；帧率低于 20 立即关掉物体检测和姿态 |

### 最重要的取舍

> **宁可少判，不可误判。**
>
> 用户被错误记了 5 次分心，会立刻不信任整个产品。漏判几次没人会发现。
> **所有阈值优先调保守，其次才是灵敏。**

**F10 的调参方法（和 F2 不一样，要单独做一次）**：让 2 个人各正常学习 10 分钟，把 `ex / ey` 序列导出，看两件事：
1. 基线的 `stdEx` 有多大。如果大于 0.04，说明摄像头画质或光线不够，先解决硬件而不是调阈值。
2. 10 分钟里 `GAZE_DRIFT` 触发了几次。真人正常学习时应该 **0–2 次**，超过 5 次说明阈值太松。

**调参方法**：让用户坐着正常学习 5 分钟，看日志里各事件的触发次数。如果 5 分钟内 `TURN` 超过 15 次，说明阈值太松（30° 不够），加到 35°。如果 `GAZE` 一次都没触发，说明太严，减 500ms。
