# 技术边界与信号路线

> 一句话：**把"读表情、读眼神"降级为辅助，把"读动作"升级为主线。**
>
> 这份文档回答四个问题：现在真正的技术难点是什么、哪些必须放弃、放弃之后走哪条路、每个动作该用哪个开源模型。

---

## 0. 先承认三件事做不到

| 做不到 | 为什么 | 硬数据 | 处置 |
|---|---|---|---|
| **可靠的情绪识别** | RGB 摄像头分不清"皱眉思考"和"皱眉生气"；亚洲人表情幅度偏小 | 最好的开源模型 HSEmotion `enet_b2_8` 在 AffectNet 八类 **63.0%**、七类 **66.3%**；FocusTrack 自训 CNN **59.28%**；人类在 FER2013 上约 **65%** | **不叫"情绪识别"，改叫"面部状态占比"**，只在报告里给分布，不给结论 |
| **靠眼神判断所有走神** | 眼睛必须可见。低头写字时摄像头只能看到头顶 | 场景 A 下 G1/G2 全部失效 | **按场景切换信号源**，见第 2 节 |
| **实时精确判定"发呆"** | 发呆没有正向动作，只有"动作停止"这个负向特征 | 注视凝固只在直视屏幕时有效（约 8 秒窗口） | **两个场景两套判据**：屏幕前看注视，纸面前看手停 |

> 这三条不要试图硬做。花两天把 63% 的情绪模型接进来，不如花半天把"停笔 15 秒"做准。**后者评委一看就懂，前者怎么讲都心虚。**

## 1. 关键转向：从"读表情"到"读动作"

表情和眼神都是**小位移、高噪声**信号：虹膜在 640×480 下只有 10px，表情分数在 0.1 附近浮动。

动作是**大位移、低噪声**信号：抬手是几十到上百像素，低头是 20 度以上。

| | 表情 / 眼神 | 动作 |
|---|---|---|
| 信号幅度 | 像素级 | 几十像素到整屏 |
| 噪声 | 高（虹膜抖动、表情漂移） | 低 |
| 需要校准 | 部分是 | **完全不需要** |
| 需要训练 | 是（且只有 63%） | 否（规则即可） |
| 可解释性 | "模型输出 0.71" | "你的手停了 15 秒" |
| 答辩可讲性 | 弱 | **强** |

**结论：动作检测是这次最该投入的地方。** 它同时满足"准确、免校准、可解释、好演示"四个条件，而表情一个都不满足。

## 2. 两个场景 = 两套传感通道

这是整个方案的结构性决定：**不是一套模型硬套所有人，而是根据你在做什么，切换用哪路信号。**

### 场景 A · 纸质学习（写字、看书、做卷子）

摄像头在笔记本上，用户低头，**视野里主要是头顶和侧脸，虹膜基本不可见**。

所以场景 A 里所有"看眼睛"的判断都要关掉。可用的信号全部来自**头和手**：

| 信号 | 判据 | 含义 |
|---|---|---|
| 低头姿势 | `pitchDeg` 稳定在 +15°~+45° | 正常状态，不是分心 |
| 书写节律 | 手部关键点位移能量在正常区间 | 在写 |
| **停笔** | 位移能量 < 阈值持续 **15 秒** | 卡住或走神，**场景 A 的核心判据** |
| 翻页 | 手部大幅横移 + 头微抬，1 秒内完成 | 在推进 |
| 抬头 | `pitchDeg` 回到 0 附近 > 5 秒且手不动 | 视线离开纸面 |
| 离座 | `present === false` > 2 秒 | 最确定的分心 |

> **场景 A 里，"手"代替了"眼"。** 发呆的证据不是眼球不动，是笔停了。而且这个判据比注视凝固可靠得多：手停了就是停了，没有歧义。

### 场景 B · 电脑学习（看网课、写代码、刷题）

头正对屏幕，眼睛可见。这一套就是 F2 + F10：

| 信号 | 判据 | 含义 |
|---|---|---|
| 眼头不一致（G1） | 眼内偏移超基线 ±3σ 持续 2 秒 | 眼睛飘走了 |
| 注视凝固（G2） | 8 秒内跳视 < 5 次且眼不偏 | 盯着不读 |
| 眨眼节律（G3） | 双向异常 | 走神型 / 疲劳型 |
| 头姿（F2/F3） | yaw/pitch 偏离基线 | 转头、抬头、低头 |
| 离座 | `present === false` | 离开 |

### 场景决定引擎开关

```js
const SCENARIO = {
  paper: {          // 写字 / 看书
    face: 30, hand: 15, pose: 2, object: 0,
    gaze: false, stare: false,        // 眼睛看不见，全关
    posture: true, writeMotion: true, // 改成看手
  },
  screen: {         // 看网课 / 写代码 / 刷题
    face: 30, hand: 5, pose: 0, object: 1,
    gaze: true, stare: true,          // F10 全开
    posture: true, writeMotion: false,
  },
};
```

这同时解决了一个性能问题：**两个场景各跑各的模型，不用四个模型同时 30fps。**

## 3. 可统计动作清单（哪些能做，哪些别碰）

| 动作 | 判据 | 依赖 | 可靠性 | 难度 | 建议 |
|---|---|---|---|---|---|
| 离座 | `present=false` > 2s | Face | 高 | 已有 | ✅ 必做 |
| 低头（书写/看书） | `pitch` 稳定在 +15°~+45° | Face | 高 | 低 | ✅ 必做 |
| **停笔发呆** | 手部位移能量 < 阈值 15s，头不动 | Hand | **高** | 低 | ✅ **场景 A 核心** |
| 翻页 | 手大幅横移 0.3~1s | Hand | 中高 | 低 | ✅ 好做 |
| 喝水 | 手腕到嘴距离 < 0.12×脸宽 且 `pitch` 上仰 > 8°，持续 1.2s | Hand + Face | **高** | 低 | ✅ 不用认杯子 |
| 摸脸 / 托腮 | 手腕到面部关键点距离 < 阈值，持续 2s | Hand + Face | 高 | 低 | ✅ 好做 |
| 撑头 | 同上 + `rollDeg` 侧倾 | Hand + Face | 中高 | 低 | ✅ 好做 |
| 伸懒腰 | 双腕高于肩线 且 肩线上移 | Pose | 高 | 低 | ✅ 场景 A 加分 |
| 驼背 | 耳肩连线与垂直夹角 > 25° | Pose | 中 | 中 | ⭕ 可选 |
| 看手机 | COCO `cell phone` 检测 + 低头 | Object | 中 | 中 | ⭕ 手机入镜才算 |
| 转笔 | 指尖轨迹圆形度 + 周期性 | Hand（需调参） | 中 | 中高 | ❌ 见第 5 节，建议不做分类 |
| 抖腿 | 需要看到下半身 | — | 不可行 | — | ❌ 放弃 |
| 桌下玩手机 | 手机不在画面里 | — | 不可行 | — | ❌ 放弃，只能靠低头推断 |

**两个必须说清的边界**：

1. **看手机**这个统计的真实含义是"低头 + 手机入镜"。用户把手机放在桌下刷，摄像头拍不到，只能靠 `pitch` 推断，所以报告里必须写"低头（可能在看手机）"，不能写"看了 3 次手机"。
2. **转笔**不建议单独识别。它对报告的洞察价值很低（告诉你"你转了 12 次笔"没有用），但需要采数据调参。把它归进"手部活动"就够了。

## 4. 模型选型（全部开源、全部可本地跑）

### 关键前提：不用再引任何新运行时

现有 `vendor/mediapipe/vision_bundle.mjs` **已经导出了下面全部四个类**，我验证过：

```
HandLandmarker  PoseLandmarker  ObjectDetector  FaceLandmarker
```

也就是说，**不需要装 onnxruntime-web，不需要第二个推理引擎，只要再下几个 `.task` 模型文件。**

| 任务 | 模型 | 体积 | 浏览器 | 精度 | 结论 |
|---|---|---|---|---|---|
| 人脸 / 眼 / 头姿 / 眨眼 | MediaPipe **Face Landmarker** | 3.6MB | ✅ 已有 | 高 | **保留，主信号** |
| 手部 21 点 | MediaPipe **Hand Landmarker** | ~7.8MB | ✅ 同一运行时 | 高 | **新增，场景 A 核心** |
| 身体 33 点 | MediaPipe **Pose Landmarker**（lite） | ~5.5MB | ✅ 同一运行时 | 高 | 可选，坐姿/伸懒腰 |
| 物体 80 类 | MediaPipe **EfficientDet-Lite0**（int8） | 4.6MB | ✅ 同一运行时 | 中（COCO mAP 约 25 量级） | **够用**，手机/水杯/书/笔电都在 COCO 里 |
| 更高精度物体检测 | **YOLO11n**（ONNX） | ~5.4MB | ⚠️ 需 onnxruntime-web | 较高（COCO mAP 约 39 量级） | 只在 Lite0 明显不够时换，会多引一个运行时 |
| 表情（如果一定要做） | **HSEmotion** `enet_b2_8`（ONNX） | ~15MB | ⚠️ 需自己接预处理 | AffectNet 八类 **63%** | **不建议**，见第 0 节 |

> 体积与 mAP 是官方公开数据的量级参考，接入前用你们自己那台机器实测一次帧率，别信纸面数字。

**为什么优先用 MediaPipe 的 EfficientDet 而不是 YOLO**：多一个运行时就是多一条部署链、多一份现场翻车风险。而且你们要做的是"手机有没有出现在画面里"这种大目标检测，不需要 YOLO 的精度。**5 个百分点的 mAP 换一个 onnxruntime-web，不划算。**

### 性能预算：必须分频，不能每帧全跑

30fps 下每帧只有 33ms：

| 模型 | 频率 | 单帧耗时（估） | 摊到每帧 |
|---|---|---|---|
| Face | 30fps | 10~20ms | 15ms |
| Hand | 10~15fps | 8~15ms | 4ms |
| Object | 1~2fps | 10~20ms | 1ms |
| Pose | 1~2fps | 10~15ms | 1ms |
| **合计** | | | **约 21ms，留 12ms 给渲染** |

**如果四个模型都跑 30fps，总耗时会到 60ms 以上，直接掉到 15fps。** 分频调度是硬要求，不是优化项。

## 5. 需要你们采数据 / 调参的，只有两件

### ① 停笔阈值（必须做，半天）

不需要训练，只需要**采 3 段真实数据**定阈值：

- 认真写字 3 分钟（正样本，算位移能量分布）
- 停笔发呆 1 分钟（负样本）
- 翻页、挠头、拿东西（干扰样本）

输出：手部位移能量的 P5（认真写时的低值）和 P95（发呆时的高值）。阈值取两者中间。

**这一步不做，停笔判定就是瞎猜。**

### ② 转笔（不建议做，如果一定要做）

需要训一个极小的分类器，因为"笔"不在 COCO 的 80 类里，抓手部关键点也认不出笔：

- 特征：42 维（两手 21 点，归一化到手腕为原点、按手掌尺寸缩放），加每 2 秒窗内的均值、方差、指尖轨迹圆形度、角速度
- 样本：转笔 150 段、写字 150 段、敲键盘 150 段、静止 150 段，每段 2 秒
- 模型：逻辑回归或 kNN，几十行 Python，不需要 GPU

**我的建议是不做。** 收益太低（报告里多一行"转笔 12 次"），成本是半天采数据加半天调参。这半天的价值远不如把停笔判定调准。

## 6. 护眼：两个场景都要，但指标不同

护眼不但要保留，**在场景 A 里其实更重要**：写字时视距常常不到 30cm，低头角度大，颈椎和近视风险都比看屏幕高。

| 指标 | 场景 A（纸面） | 场景 B（屏幕） |
|---|---|---|
| 视距 | 用**脸框宽度**估算（低头时 `distanceCm` 不准） | `frame.distanceCm` |
| 低头时长 | **核心指标**，连续 > 20 分钟提示颈椎 | 不适用 |
| 连续用眼 | ✅ | ✅ |
| 眨眼频率 | 只在头抬起时采，低头时数据无效 | ✅ |
| 远眺提醒 | ✅ 20-20-20 | ✅ |

> 场景 A 的 `distanceCm` 基于瞳距，低头侧脸时瞳距会被压缩，算出"距离 90cm"这种明显错误的值。**必须换成脸框宽度或耳距估算，否则护眼数据是假的。**

## 7. 报告里能写什么，不能写什么

| 能写 | 不能写 |
|---|---|
| 「低头 42 分钟，其中停笔 6 次，最长 2 分 10 秒」 | 「你走神了 6 次」 |
| 「喝水 3 次，伸懒腰 1 次」 | 「你今天情绪低落」 |
| 「面部状态：平静 78%、皱眉 15%、放松 7%」 | 「你的压力指数 63」 |
| 「被打断 7 次，每次重新接上平均要 20 分钟以上」（附文献） | 「你损失了 2.5 小时深度专注」 |
| 「离座 2 次，共 4 分钟」 | 「自律评分 62 分，超过 38% 用户」 |

**最后一条尤其注意**：25 分钟的会话里不可能损失 2.5 小时，这种乘法一算就崩。而且原研究量的是"回到原任务的时间"，不是"恢复专注深度的时间"。引用要克制。

## 8. 答辩怎么说（这段直接背）

> "我们只统计能看见的东西。
>
> 你低头、你停笔、你离座、你抬手到嘴边、你转头看别处，这些是动作，动作骗不了人，也不需要校准。
>
> 至于你在想什么，我们不做判断。市面上说能读情绪的，用的模型在公开数据集上也就六成准确率，比抛硬币好一点。**我们宁可少说一句，也不编一个数字。**"

这段话有两个作用：**把技术短板转成诚实标签**，同时暗示"我们知道那些产品在吹"。评委听到这里通常会点头。

## 9. 落地顺序

| 优先级 | 做什么 | 时间 |
|---|---|---|
| P0 | 场景选择（纸质/电脑）+ 引擎开关 | 2h |
| P0 | 手部模型接入 + 停笔判定（场景 A 核心） | 4h |
| P0 | 停笔阈值实测标定 | 2h |

| P2 | 姿态（伸懒腰、驼背） | 3h |

## 10. 做不做的判断标准

只一条：

> **这个功能能不能变成报告里一句用户在意的话？**

能，就做。不能，不管技术上多酷，都是负资产：它占开发时间、占答辩时间，还会在评委追问时暴露短板。

用这条标准去量：

| 功能 | 能产出的那句话 | 判断 |
|---|---|---|
| 停笔判定 | "你写了 42 分钟，停了 6 次，最长一次 2 分 10 秒" | ✅ 用户会在意 |
| 眼头不一致 | "有 3 次你的眼睛离开屏幕超过 2 秒" | ✅ 会在意 |
| 情绪分析 | "你的挫败指数 0.62" | ❌ 不在意的假数字 |
| 转笔统计 | "你转了 12 次笔" | ❌ 有趣但无用 |

### 四个难点的取舍

| 难点 | 值不值得 | 理由 | 怎么处置 |
|---|---|---|---|
| **情绪分析** | ❌ **砍** | 63% 的准确率只支撑得起一句"仅供参考"，却要吃掉两天 | 保留报告里"面部状态占比"一行，用现有 blendshape 直接算，**不接任何模型** |
| **发呆检测** | ⚠️ **打折** | 场景 B 的 G1（眼头不一致）值得，因为它进专注率；G2（注视凝固）只值一个标签 | 只做 G1 加场景 A 的停笔，G2 有时间再说 |
| **手部动作** | ✅ **最值** | 场景 A 唯一可靠的信号源，且天然产出人话 | 最高优先级，但**先验证摄像头拍不拍得到手** |
| **性能** | ✅ **必须** | 它不是功能，是前提。不分频就直接跑不动 | 分频调度写成代码约束，帧率低于 20 立刻关 P2 模型 |

一句话：**四条里砍一条、打折一条、两条必做。**

### 五个便宜的增量建议（按性价比排）

**① 恢复时间：把那条用不了的文献变成自己的指标**

Mark 的 23 分钟不能抄（那是别人的数据，且量的不是"专注深度"）。但可以测自己的：

```js
// 一次分心事件结束后，专注度回到该次分心前水平的 90% 所需时间
// 只统计 ≥30 秒的分心，避免噪声
const recoveryMs = timeToReach(0.9 * beforeScore);
```

报告里写：「7 次分心里，4 次你在 30 秒内就拉回来了，最长一次花了 6 分半。」

**这句话的力量在于它是关于"你"的**，不是引用别人的平均数。而且它顺手把"打断有代价"这件事讲清楚了，不用编任何数字。

成本：半天，纯计算。

**② 卡点聚类：从"计数"升级到"归因"**

现在报告说"你分心 7 次"，用户看完不知道该改什么。把事件按时间聚成簇（间隔小于 3 分钟算同一簇）：

> 「你的分心集中在第 12–18 分钟和第 31 分钟之后。前一段你盯着一页看了很久，可能是卡住了。」

一句话就把"你不专心"变成"你卡住了"。这是产品态度的分界线。

成本：2 小时。

**③ 骨架剪影回看：报告里放火柴人，不放照片**

不存任何照片，只存 33 点身体关键点的坐标。报告里画三个火柴人：最专注时的姿势、最散的时候的姿势、平均姿势。

- **隐私安全**：骨架还原不出人脸，比截图安全一个量级
- **视觉冲击**：一张图就能让评委看懂"你塌下去了"
- **和"不录像"的主张一致**：你们敢说"我们只存骨架"，这句话很硬

成本：半天（含画图）。

**④ 专注指纹：一次会话一张波形图**

横轴时间、纵轴专注度，配色渐变，形状像指纹。可导出 PNG 分享。

它同时干三件事：报告的可视化主体、朋友圈传播素材、答辩 PPT 的封面图。

成本：3 小时，数据现成（时间轴已经在算了）。

**⑤ 状态驱动休息：把番茄钟从"定时"改成"看状态"**

不再固定 25 分钟。检测到专注度连续 3 分钟低于 50，才提议休息（不强制，可关）。

这是和所有番茄钟类产品最直接的差异点：**别人按时间提醒，我们按状态提醒。** 一句话能讲清，评委也容易记住。

风险是打断，所以只在"连续下降"时提议，单次会话最多提 2 次。

成本：半天。**时间不够就砍，它的价值主要在叙事。**

### 明确不要做的

| 不做 | 为什么 |
|---|---|
| 云端排行榜、多用户 | 要后端、要用户量，数据一定是假的。评委一问就崩 |
| 真实情绪模型 | 见第 0 节，63% 撑不起任何结论 |
| 录视频回看 | 和"不上传、不落盘"的隐私主张直接冲突 |
| 转笔分类 | 收益一行字，成本一天 |
| 手机 App / 小程序 | 黑客松现场没人愿意装包，扫码即用才有意义 |
