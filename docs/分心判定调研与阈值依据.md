# 分心判定调研与阈值依据

> 配套文档：`开发文档-自律学习版.md`
> 目的：为 F2 分心引擎的阈值找依据，而不是拍脑袋定数字。
> 调研日期：2026-11-26

---

## 0. 结论先行

三层都找到了东西，不用自己从零摸索：

| 层级 | 结果 | 对本项目的价值 |
|---|---|---|
| ① 同类项目 | **有 5 个高度相关**，其中 FocusTrack 几乎是同款 | 架构、状态分类、报告形态可直接参照 |
| ② 现成算法 | **有成熟方案**：EAR / MAR / 头姿角 / 规则引擎 | 我们的技术路线是对的，参数有参照 |
| ③ 学术阈值 | **有明确数字**：驾驶分心 2s、课堂 3s、pitch −15°、yaw ±25° | 阈值有了硬依据 |

**最重要的发现有两条**：

1. **情绪识别这件事，被现成项目的数据证实了不能吹。** FocusTrack 用 FER2013 训练 7 类情绪 CNN，测试准确率只有 **59.28%**，而论文里人类在 FER2013 上的基线也只有约 **65%**。一个专门做情绪分类的模型都只有六成，我们靠 blendshape 做个加权，绝不能写准确率。
2. **驾驶和课堂的阈值不能直接搬到学习场景。** 原因见第 4 节——这是整份文档最需要组员理解的地方。

## 1. 第一层：现成项目对比

### 1.1 FocusTrack（最接近，建议重点参考）

`github.com/0AnshuAditya0/focus-track`

| 项 | 做法 |
|---|---|
| 情绪 | 自训 7 类 CNN（FER2013，28,709 张），准确率 59.28% |
| 眼睛 | Haar Cascade 检测双眼，算眨眼率、注视居中 |
| 分心判定 | **规则引擎**：情绪 + 眼状态 → Focused / Distracted / Drowsy |
| 输出 | Session dashboard：时间轴、productivity score、眨眼率曲线 |
| 示例结果 | 时长 1m18s，生产力 83%，专注 83.8%，分心 13.5%，困倦 2.7% |

**可借鉴**：
- 三态分类（专注 / 分心 / 困倦）而不是二分类——我们文档里 6 种事件，报告里可以归并成三态
- 输出「生产力分数」这个单一指标，比一堆数字更好懂
- 用规则引擎而不是端到端模型——和我们的选择一致

**不借鉴**：Haar Cascade 检测眼睛太老，我们用 MediaPipe 虹膜点，精度高一个量级。

### 1.2 Concentration Tracker（权重公式可直接用）

`github.com/MadScie254/concentration_tracker`

MediaPipe FaceMesh + 三路信号融合：

```
concentration = 0.4 × gaze + 0.4 × head_pose + 0.2 × (not blinking)
```

**可借鉴**：这就是我们 F5 专注度公式的现成参照。我们的版本多了「在座率」和「表情投入」两项，可以对齐成：

```
focusScore = 0.35 × presentRatio + 0.25 × gazeStability + 0.20 × headStability + 0.20 × engagement
```

> 注意：他们的 0.2 权重给「不眨眼」不太合理——专注时本来就会减少眨眼，把不眨眼当加分会让「盯到眼睛发干」得高分。我们用「在座率」替代更合理。

### 1.3 StudyEyes（参数最完整，三个数字必抄）

`github.com/SahilAGowda/study-eyes`

6 种行为状态 + 明确的工程参数：

| 参数 | 值 | 作用 |
|---|---|---|
| **眨眼豁免** | **300ms** | 自然眨眼不判分心 |
| **状态平滑** | **3 秒** | 防止瞬时瞟一眼就闪成"分心" |
| **容差边界框** | **外扩 30%** | 眼睛在框边缘不算看走 |
| 参与度打分 | 专注 +10 / 说话 +5 / 记笔记 +8 / 看别处 −5 / 无人 −10 / 手机 −15 | 滑动累计 |
| 窗口 | 60 秒滚动 | — |

**可借鉴**：
- **300ms 眨眼豁免必抄**——我们原文档漏了这条，会导致每次眨眼都触发状态跳变
- **3 秒平滑**比我原文档的 500ms 退出防抖更稳，建议提上来
- 60 秒滚动窗口与我们的 F5 一致

### 1.4 另外两个（参考价值较低）

- **Attention-Detector**（shubZk17）：SVM 图像分类，22,000 张图。做法黑盒、不可解释，不适合我们。
- **EngageVision**（Manoj-2702）：MediaPipe 头姿 + 注视，理念和我们最接近，但代码较旧、无报告体系。

## 2. 第二层：现成算法与工程参数

### 2.1 面部指标的定义

| 指标 | 公式 | 用途 |
|---|---|---|
| **EAR**（眼纵横比） | `(‖p2−p6‖ + ‖p3−p5‖) / (2‖p1−p4‖)` | 眨眼、闭眼、打盹 |
| **MAR**（嘴纵横比） | 类似 EAR，取嘴部 6 点 | 打哈欠 |
| **头姿角** | solvePnP 或 transformation matrix → yaw / pitch / roll | 转头、抬头、低头 |
| **注视点** | 虹膜相对眼角归一化 → 回归 | 视线游离 |

**我们的优势**：`vision.js` 里 `yawDeg` / `pitchDeg` / `rollDeg` 已经是**真实角度**，不用自己解 PnP，直接能用。

### 2.2 一篇直接对口的论文（Zenodo, 2026）

《Real-Time Driver Drowsiness and Distraction Detection Using Facial Landmark Analysis》

| 参数 | 论文取值 |
|---|---|
| EAR 阈值 | **0.22** |
| MAR 阈值 | **0.50**（打哈欠） |
| 低头 pitch | **−15°** |
| 转头 yaw | **±25°** |
| 平滑 | EAR / MAR 做 **5 帧移动平均** |
| 触发 | **连续 15 帧**（≈0.5s@30fps）才报警 |

这篇的价值在于：**它用的也是 MediaPipe Face Landmarker**，和我们的技术栈完全一致，参数可以直接当起点。

论文自己也声明「没有标注数据集，因此不声称准确率 / 召回率」——这个态度值得学。

## 3. 第三层：学术与行业阈值

### 3.1 视线偏离多久算分心

来自驾驶分心研究（超星慕课《驾驶员视觉分散特征识别》）：

| 结论 | 数值 |
|---|---|
| 正常状态下，视线 80–90% 时间在 **±12°** 范围内 | ±12° |
| 发生视觉分散时，只有不到 50% 时间在 ±12° 内 | — |
| 偏离 < 1 秒对表现影响不大 | 1s |
| **偏离 > 2 秒即判定为视觉分散** | **2s** |
| Blanco「红线」：偏离 > 9 次，或单次 > 2.5s | 2.5s |
| 汽车制造协会标准：2s，或 20 秒内 10 次 | 2s / 10 次 |

### 3.2 头部角度阈值

| 来源 | 低头 | 侧转 |
|---|---|---|
| 车载 DMS（商用方案） | > **30°**，持续 > 2s | > **45°**，持续 > 2s |
| Zenodo 论文 | **−15°** | **±25°** |
| 课堂专注度系统 | — | > **45°** 且持续 |

> 差异很大（−15° 到 30°，25° 到 45°），原因是**场景不同**。见下一节。

### 3.3 课堂场景的一条关键经验

来源：《课堂专注度识别系统技术解析》

> 「视线游移的阈值我调了很久，最后定为**单次游移超过 3 秒才算一次分心事件，低于 3 秒的快速扫视属于正常课堂行为**。」

这条直接说明：**正常人的视线本来就会不停扫动**，把任何一次偏离都算分心，产品必然废掉。

### 3.4 注意力持续时间（决定产品节奏）

| 研究 | 结论 |
|---|---|
| Bradbury (2016), *Advances in Physiology Education* | 持续注意力在 **10–15 分钟**达峰，**20–25 分钟后显著下降** |
| Ariga & Lleras (2011), *Cognition* | 短暂休息可让表现维持 **50 分钟**不衰减 |
| Kleitman (1982), *Sleep* | 人体存在 **90–120 分钟**的超昼夜节律 |
| Mark, Gonzalez & Harris (2005), CHI | 被打断后**回到原任务**平均 **23 分 15 秒**（同一研究：同日恢复平均 25 分 26 秒；外部打断 22 分 37 秒；恢复前平均先处理 2.26 件别的事） |
| 综述结论 | 成年人最佳专注区间 **20–45 分钟** |

**对本项目的用处**：
- 默认时长 25 分钟有据可依，不是随便定的
- 报告里可以引用「每次被打断，平均要 20 分钟以上才能重新接上原来那件事」作为解释性注脚（Mark et al., 2005）
- **不要做乘法估算**。「打断 7 次 × 23 分钟 = 2.5 小时」这种算法一算就崩：25 分钟的会话不可能损失 2.5 小时。而且原研究量的是"回到原任务的时间"，不是"恢复专注深度的时间"，两者不等价
- 90 分钟属于长会话，需要在报告里提示「已超出多数人的最佳区间」

## 4. 关键：为什么阈值不能照搬

这是整份文档最需要理解的一节。同样是「转头 30 度持续 2 秒」，在不同场景下结论完全不同：

| 场景 | 误判的代价 | 漏判的代价 | 阈值策略 |
|---|---|---|---|
| **驾驶监控** | 误报烦人但无害 | **可能致命** | **从严**：宁可误报，绝不漏报（所以用 2s、−15°） |
| **课堂监测** | 老师误判学生，学生反感 | 漏掉走神的学生 | 中等，容许误差 |
| **学习自律（我们）** | **用户失去信任，直接卸载** | 少记几次分心，没人发现 | **从宽**：宁可漏判，绝不误判 |

**结论：我们的阈值必须比驾驶场景更宽松。**

一个用户被错记 5 次「分心」，会立刻觉得「这软件根本不准」，然后关掉再也不开。反过来，漏记几次，他自己心里也没数——**这就是不对称的代价**。

所以：

> **驾驶用 2s / −15° / ±25°，我们要更宽。**
> **但不能宽到没意义——参考课堂场景的 3s，加上 2.5s 的持续判定，是合理区间。**

## 5. 最终推荐阈值表

综合三层调研，给出可直接落地的数值。**这是对开发文档第 3 节 F2 的修订版。**

```js
// src/core/thresholds.js
export const T = {
  // ── F2 分心事件 ──────────────────────────────
  awayMs:        2000,   // 离座（人脸丢失），驾驶/工程通用值

  downDeg:       22,     // 低头：介于 Zenodo 15° 与驾驶 30° 之间
  downMs:        2500,   // 持续判定，对齐驾驶 2s 与课堂 3s 的中点

  upDeg:         18,     // 抬头：抬头幅度通常小于低头，阈值收紧
  upMs:          2500,

  turnDeg:       30,     // 转头：比 Zenodo ±25° 宽，比驾驶 45° 严
  turnMs:        2500,

  gazeOffMs:     3000,   // 视线游移：直接采用课堂场景的 3 秒
  drowsyOpen:    0.35,   // 闭眼度（对应 EAR≈0.22 的 blendshape 等价）
  drowsyMs:      1500,   // 打盹要比分心更敏感，1.5 秒就提醒

  blinkForgiveMs: 300,   // ★新增 自然眨眼豁免（StudyEyes）
  exitQuietMs:   1200,   // 退出防抖：从 500ms 提到 1200ms，防止反复横跳
  smoothFrames:  5,      // 5 帧中值平滑（Zenodo 论文做法）

  // ── F3 头位统计（只计数，不进专注率，可更宽松）──
  postureUpDeg:  14,
  postureDownDeg: 18,
  postureTurnDeg: 25,
  postureMs:     800,

  // ── F4 情绪 ─────────────────────────────────
  emaAlpha:      0.12,
  emoWindowMs:   3000,

  // ── F5 专注度 ────────────────────────────────
  scoreWindowMs: 60000,

  // ── 基线采集 ─────────────────────────────────
  baseSampleMs:  5000,
};
```

### 5.1 与初版开发文档的差异

| 参数 | 初版 | 修订 | 原因 |
|---|---|---|---|
| `turnDeg` | 25° | **30°** | 25° 是驾驶级敏感度，学习场景看旁边屏幕就会误判 |
| `downDeg` | 18° | **22°** | 低头记笔记也在这个区间，太松会误判「记笔记=走神」 |
| `gazeOffMs` | 4000 | **3000** | 课堂实测 3 秒足够，4 秒会让分心漏统计 |
| `drowsyMs` | 3000 | **1500** | 打盹是强信号，应更早提醒 |
| `exitQuietMs` | 500 | **1200** | StudyEyes 用 3s 平滑，500ms 太短会抖 |
| `blinkForgiveMs` | — | **新增 300** | 原方案漏了眨眼豁免，会导致每次眨眼触发状态跳变 |

### 5.2 头姿基线怎么取

所有角度都是**相对值**，不是绝对值。因为每个人坐姿不同：

```js
// 会话开始后前 5 秒，取俯仰角中位数作为零点
base.pitch = median(frames.slice(0, 150).map(f => f.pitchDeg));
base.yaw   = median(frames.slice(0, 150).map(f => f.yawDeg));
```

之后用 `pitchDeg - base.pitch` 判定。**换了坐姿就要重新取基线**，否则整套判定失效。

## 6. 判读方法选型：为什么用规则引擎

调研里有两类做法：

| 做法 | 代表 | 优点 | 缺点 |
|---|---|---|---|
| **规则引擎** | FocusTrack、StudyEyes、Zenodo 论文、车载 DMS | 可解释、可调参、不需要训练数据、单帧开销可忽略 | 阈值要手工调 |
| **端到端分类模型** | Attention-Detector（SVM）、FocusTrack 的情绪部分 | 省事 | 黑盒、不可解释、需要大量标注 |

**我们选规则引擎，三条理由：**

1. **没有标注数据**。我们没法收集"这是分心、这是专注"的标注集去训练。
2. **答辩要能解释**。评委问"你怎么判断我在分心"，能回答"你的头部俯仰偏了 22 度，持续 2.5 秒"——这比"模型输出 0.73"有力一百倍。
3. **现场要能调**。演示时如果误判，改一个数字就能修好；模型只能重训。

### 混合策略（可选，时间够再做）

课堂系统的做法值得借鉴：**规则处理高置信度，分类器处理模糊场景**。

- 高置信度（人脸消失、低头 30°、闭眼 1.5s）→ 规则直接判
- 模糊场景（头偏 5°、视线轻微偏移）→ 不判分心，只在分数上扣一点

我们的 F5 专注度分数天然承担了「模糊场景」的表达：不判事件，但分数会下降。**这已经是混合策略了，不用额外做分类器。**

## 7. 可以直接写进报告的三个"硬数字"

这些有文献支撑，比自造指标有说服力：

1. **「被打断后平均要 20 分钟以上才能回到原来那件事」**（Mark, Gonzalez & Harris, 2005, CHI）
   用法：**只做定性说明**，不做时间乘法。原话是"回到原任务"，不是"恢复专注深度"。另注意常被误引为 Mark et al. 2008，那篇讲的是"被打断后速度更快但压力更高"，不是 23 分钟

2. **「成年人最佳专注区间 20–45 分钟，20–25 分钟后注意力显著下降」**（Bradbury, 2016）
   用法：解释为什么 25 分钟一轮，以及超过 45 分钟要提示

3. **「短暂休息能让表现维持 50 分钟不衰减」**（Ariga & Lleras, 2011）
   用法：鼓励用户真的去休息，而不是继续刷手机

## 附：给组员的一句话

> 阈值不要凭感觉调，也别照抄别人的。
> **先按这张表跑一轮，然后拿真实数据看：5 分钟内某个事件触发超过 15 次，说明这个阈值对你不适用，加 5 度或加 1 秒。**
> 每个人的脸型、坐姿、摄像头角度都不同，阈值调参是产品的一部分，不是 bug。
