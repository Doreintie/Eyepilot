# EyePilot · 瞳行 — 提案书

> **AI + 眼睛**：让眼睛成为输入设备，也让用眼健康第一次变得「可测量、可干预」。

| 项目 | 内容 |
| --- | --- |
| 作品名 | EyePilot · 瞳行 |
| 赛道主题 | AI + 眼动交互 / 视觉健康 |
| 形态 | 浏览器端应用 + Electron 桌面版（纯前端，本地推理） |
| 硬件依赖 | 普通笔记本摄像头（无需红外眼动仪） |

## 一、问题：两个被割裂的现实

**1. 交互的入口被手占满了。**
我们每天在鼠标和键盘之间切换上千次。对大多数人这只是麻烦，但对运动功能障碍、渐冻症、严重关节炎患者，这是一道无法跨越的门槛。商用眼动仪（如 Tobii）价格动辄上万元，需要专用硬件和安装调试，几乎只存在于实验室和特殊教育学校。

**2. 用眼健康是「不可见的」。**
眼科门诊里医生会问：「你一天看屏幕多久？」——没人答得准。眨眼频率、闭眼时长、注视距离这些真正决定视疲劳的变量，在日常生活里完全不可观测。于是护眼只能靠「20-20-20」这类口号，靠意志力，靠事后配眼镜。

这两件事看似无关，其实共享同一个信号源：**眼睛的位置与开合**。而每一台笔记本都已经有一个能拍到眼睛的摄像头。

---

## 二、方案：一颗摄像头，两条能力

EyePilot 用同一套视觉管线，同时产出两类结果：

```
摄像头 → 478 点面部网格 ┬→ 虹膜几何 ─┐
                        ├→ 头部姿态 ─┼→ 四档控制映射 → 指针（输入）
                        └→ 行为统计 ─┴→ 用眼健康（感知）
```

- **作为输入**：四种控制方式构成一条**回退链**——头部（零校准）、混合（零校准）、眼控（20 秒校准）、仅鼠标（零）。精度不够就往下退一档，永远有一条路能走通；注视目标 0.8 秒即点击，长眨眼也可触发，桌面版还能接管系统鼠标、在任何程序里使用。
- **作为感知**：眨眼频率、闭眼占比（PERCLOS）、视距、环境光、专注度、疲劳指数实时计算；异常时提醒，按 20-20-20 节律带用户远眺，并提供六节眼保健操引导。
- **作为教练**：AI 把指标翻译成「现在该做什么」，学习每个人的眨眼基线，预测疲劳趋势，生成可下载的用眼报告。

**关键取舍**：不做硬件，**也不赌单一精度假设**——普通摄像头做不到实验室级精度，所以我们用多档信号源覆盖整条精度曲线，而不是硬撑一个数字。把「足够好 + 零成本 + 可解释 + 隐私安全」做到极致，这是一个打开摄像头就能用的产品，而不是一台需要采购的设备。

## 三、技术方案

### 3.1 视觉管线

| 环节 | 实现 | 参数 / 说明 |
| --- | --- | --- |
| 人脸关键点 | MediaPipe Face Landmarker（WASM + GPU delegate，失败自动回退 CPU） | 478 点 + 52 个 blendshape，约 30 FPS，单帧 10–20ms；模型与运行时全部内置本地，首次加载不联网 |
| 眼部特征 | 虹膜中心相对「内外眼角连线中点」，以眼宽为单位 | 眼角不随眨眼移动，垂直稳定性比「眼框包围盒」提升一个量级；1 像素关键点抖动不再等价于 5% 特征变化 |
| 头部姿态 | 脸侧两点（234/454）与额头/下巴（10/152）的 z 差取 atan | 输出**真实角度（度）**，不是归一化相对值，阈值可直接调 |
| 眼控映射 | 九点校准 + 标准化岭回归（λ≈0.9，截距不惩罚），校准末尾每轴仿射校正 | 9 个样本可训练，单帧 <0.1ms；另提供 5 点精细对齐与 16 点二阶模型 |
| 头部映射 | 角度线性映射到屏幕，±8° 水平 / ±5° 垂直覆盖全屏 | 限速逼近 + 44px 死区（带迟滞：出 44 动、进 15 停），静止时零抖动 |
| 混合映射 | 头部给基座，虹膜只贡献 **±110px 残差**并在边界截断 | 虹膜模型再差，最坏偏差也被锁在 110px 内；残差走 5 帧中值 + 一欧元滤波 |
| 平滑 | 一欧元滤波（低通 + 速度自适应）+ 5 帧中值去跳点 | 默认强度 55，可调；低置信度时冻结光标停在最后可信位置，不朝预测点乱跳 |
| 点击 | 注视停留（默认 800ms）+ 长眨眼（>320ms） | 眨眼与 180ms 内短暂抖动不重置进度；鼠标操作后 700ms 内抑制眼控点击 |
| 系统接管 | 桌面版经 `@nut-tree-fork/nut-js` 调系统 API | 需用户显式勾选；已处理 125% DPI 缩放；网页版受沙箱限制不提供 |

### 3.2 健康指标

- **眨眼状态机**：`open < 0.35` 进入闭眼，回开时 45–900ms 记为一次眨眼；>900ms 记为长闭眼。
- **PERCLOS**：60 秒滑窗内闭眼帧占比，是 drowsiness 研究的经典指标。
- **视距**：针孔模型 `d = f · IPD_mm / ipd_px`，`f` 由 60° 水平视场估算，IPD 取 63mm。标注为「估算」。
- **专注度**：屏幕内注视比例（50%）+ 注视离散度（32%）+ 有效数据率（18%）。
- **疲劳指数**：PERCLOS 34% + 眨眼频率 22% + 闭眼时长 10% + 连续用眼 16% + 视距 10% + 离屏比例 8%。
- **个人基线**：眨眼与视距用 EMA 持续学习，所有提醒都与「你自己的基线」比较。

### 3.3 AI 层：可解释优先

- **本地推理（默认）**：规则 + 基线 + 趋势线性回归 → 结论 / 解释 / 最多 3 条动作 / 预测 / 置信度。
  断网可用，零延迟，每个结论都能追溯到具体数值。
- **在线大模型（可选）**：用户填入任意 OpenAI 兼容接口，发送**纯数值 JSON**（无图像）生成更自然的解释；超时或失败自动回退本地。
- **趋势预测**：对疲劳序列做最小二乘，估算「多少分钟后越过预警线」，把事后提醒变成事前安排。

### 3.4 隐私架构

视频帧只在浏览器内存中交给本地模型，**没有任何一帧上传**。持久化的只有校准参数和匿名数值序列，一键可清。这是我们主动设定的产品边界，而不是事后补的合规条款。

## 四、创新点

1. **把「控制」与「健康」统一到同一信号**
   市面上眼控产品只做输入，护眼软件只做提醒。EyePilot 用同一条管线同时完成两件事：你看哪里 → 帮你点；你怎么看 → 帮你歇。这带来一个别人没有的闭环——**眼控使用强度本身，就是健康数据的来源**。

2. **四档回退：不赌单一精度假设**
   这是本项目最核心的工程判断。单目摄像头没有红外，精度天然受限，与其死磕一个「够不够准」的数字，不如承认不同用户的生理条件差异极大，用四种信号源覆盖整条精度曲线：**头部（零校准、极稳、粗）→ 混合（零校准、稳且细）→ 眼控（20 秒校准、最细）→ 仅鼠标（兜底）**。精度不够就退一档，永远有一条路走得通。这也让「现场演示失败」这件事被结构性消除了——任何环境总有能用的那一档。

3. **混合模式：把两种缺陷叠成一种能力**
   头部稳但粗，虹膜准但抖。我们让头部负责定位、虹膜只贡献 ±110px 以内的残差并强制截断——**即使虹膜模型当天完全失效，最坏偏差也被锁在 110px 内**，再经限速与死区抹平。这不是简单的加权平均，而是给误差设了一个上界。

4. **零硬件门槛的眼控**
   不依赖红外、不依赖深度相机，普通摄像头 + 小样本回归即可工作；桌面版进一步接管系统鼠标，让它能作用于任何程序。这让眼控从「上万元的辅具」变成「打开网页就能用」。

5. **为真实使用打磨的交互细节**
   眨眼不重置注视进度、鼠标操作后抑制眼控点击、低置信度时冻结而不是乱跳、校准后展示实测误差而不是假装很准、使用中自校准修正头位漂移。这些细节决定眼控是「玩具」还是「能用的输入方式」。

6. **可解释、可扩展、可离线**
   岭回归 + 规则引擎让每个结论可追溯；插件 API 让任何网页能力接入眼控；模型与运行时全部内置本地，隐私与离线是默认值而不是承诺。

## 六、应用场景

| 场景 | 价值 |
| --- | --- |
| **无障碍输入** | 为运动障碍用户提供除鼠标键盘外的第二输入通道，成本从万元级降到零 |
| **长时间用眼人群** | 程序员、设计师、学生、剪辑师：把「该休息了」从口号变成有数据支撑的提醒 |

| **企业健康管理** | 匿名聚合的用眼负荷看板，用于排班与工位改造建议 |

## 七、差异化

| 对比对象 | 差异 |
| --- | --- |
| Tobii 等商用眼动仪 | 零硬件、零安装、可按需使用；精度略低但成本低两个数量级；且附带健康监测 |
| 开源眼控项目（WebGazer / visual_mouse 等） | 它们通常只有单一方案（纯虹膜或纯头部）。我们在同一套管线上做了四档回退与混合融合，并为每一档单独调过噪声模型 |
| 手机「护眼模式 / 距离提醒」 | 面向桌面真实工作场景，指标更细（PERCLOS、视距、专注度），且有眼控能力 |
| 浏览器眼控插件 | 同时做健康闭环；插件化架构；本地可解释 AI；桌面版可接管系统鼠标 |

## 八、商业模式（探索）

1. **开源核心 + 企业版**：核心算法与插件 API 开源，企业版提供团队看板、SSO、合规审计。
2. **B 端场景授权**：无障碍机构、特殊教育学校、人因实验室按席位订阅。
3. **健康数据服务（需严格授权）**：匿名聚合的用眼负荷报告，服务企业健康管理与保险精算。
4. **不做的**：不出售个人原始数据，不做广告定向，不做医疗诊断。

## 九、风险与对策

| 风险 | 对策 |
| --- | --- |
| 精度不足导致误点击 | 置信度门控、眨眼冻结、鼠标抑制、可调平滑与注视时长；校准页展示实测误差 |
| 光照/头动影响 | 四档回退本身就是对策：光照差时眼控降级为头部模式（对光照不敏感）；头位漂移用「使用中自校准」EMA 缓慢修正，超过 13° 提醒做五点对齐 |
| 隐私担忧 | 端侧推理、无图像上传、数据可一键清除、在线模型仅收数值 |
| 伦理风险（注意力监控） | 默认只服务本人；团队功能仅匿名聚合；明确禁止用于员工惩罚性考核 |
| 医疗误导 | 全站标注「非医疗诊断」，异常建议就医 |
